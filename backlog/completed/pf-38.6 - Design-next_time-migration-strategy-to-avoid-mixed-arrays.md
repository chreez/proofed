## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Risk from PF-38.1 spike: `(string | object)[]` for next_time is awkward — CookLogSection.vue line 41 does `.map(n => \`- ${n}\`)` which breaks on objects. Options: (a) always use object shape `{ text, source? }`, (b) keep strings and add separate `next_time_sources` map, (c) normalizer function. Needs decision before PF-38.2 implementation.
<!-- SECTION:DESCRIPTION:END -->

## Changes

Migrated `next_time` from `string[]` to `NextTimeEntry[]` across the full stack:

### Type system (`src/types/recipe.ts`)
- Added `NextTimeEntry` interface: `{ text: string; source?: string }` — follows the `StateNote` precedent (`{ text: string; critical?: boolean }`)
- Changed `CookLogEntry.next_time` from `string[]` to `NextTimeEntry[]`

### Component (`src/components/CookLogSection.vue`)
- Updated `renderNotes()` line 41: `n => \`- ${n.text}\`` instead of `n => \`- ${n}\``

### Recipe data (`public/recipes/atk-cinnamon-buns-ultimate.json`)
- Migrated all 5 `next_time` entries from bare strings to `{ text: "..." }` objects

### Tests (`src/components/CookLogSection.spec.ts`)
- Updated 3 test fixtures (defaultProps, empty notes test, snapshot test) from string arrays to object arrays
- All 350 tests pass, snapshot unchanged (rendered HTML is identical)

### Build
- `npm run build` passes (tests + vue-tsc + vite build)
