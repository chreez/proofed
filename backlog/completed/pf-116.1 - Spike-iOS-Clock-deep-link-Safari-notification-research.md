## Spike Complete: iOS Clock Deep Link + Safari Notification Research

### Key Findings

**iOS Clock Deep Link:** `clock-timer://` opens the Timer tab but accepts NO parameters — pre-filling duration is not possible. Recommended revising AC #6 to "Open iOS Timer" (no pre-fill). Apple Shortcuts URL scheme (`shortcuts://run-shortcut`) could work as a future enhancement but requires user to install a custom shortcut first.

**Web Notifications on iOS Safari:** Only available for PWAs installed to the home screen (iOS 16.4+). Requires manifest with `"display": "standalone"`, service worker, user gesture for permission prompt, and push server. NOT viable for proofed. in its current form as a regular website. Desktop browsers (Chrome, Firefox, macOS Safari) support `new Notification()` in regular tabs.

**Audio Playback on iOS Safari:** Autoplay is blocked, but the Web Audio API "warm-up" pattern works — call `AudioContext.resume()` during any user gesture (e.g., starting a timer), then audio can be played programmatically later (on timer completion). Key gotchas: silent switch disables Web Audio API (but not `<audio>` elements), "interrupted" state on tab switch needs handling, background timers are throttled (mitigate with Web Workers + system clock comparison).

### Impact on PF-116 ACs
- AC #4 (audio): Feasible with warm-up pattern
- AC #5 (notifications): Desktop only; iOS graceful degradation
- AC #6 (deep link): Revise — no pre-fill possible, change to "Open iOS Timer"
- Full findings with code examples written to PF-116 implementation notes
