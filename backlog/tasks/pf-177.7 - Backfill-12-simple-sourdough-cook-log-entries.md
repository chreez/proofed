## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Migrate all 12 existing `simple-sourdough` cook log entries from prose into the new structured `bake_stats` format. Timing, temps, and aliquot data currently embedded in `notes[]` prose (e.g. "5:07pm — fold 1, 75.5°F", "60% rise") gets pulled into the structured fields (`dough_temps`, `bulk_ambient_temps`, `bake_phases`, `stretch_folds`, `aliquot_rises`). `notes[]` arrays are left with only observations and judgment after backfill. Verbatim original notepad content (when available) gets preserved into the new `raw_notes` field.

This is the **exemplar backfill** — sets the pattern before any other recipe backfill drafts spin out.

## Approach

**Walkthrough mode**: agent + user work bake-by-bake in a guided session. For each bake the agent:
1. Reads the current cook_log entry
2. Proposes a structured `bake_stats` mapping based on what's parseable from prose
3. Asks the user to fill gaps (or accept "data not tracked at the time")
4. Echo-checks the proposed structure
5. Writes both `bake_stats` and `raw_notes` (if user has the original notepad text) to the entry
6. Commits that single bake before moving to the next

**Cook Log Protocol applies in full** — agent is a scribe, not an author. No inferred temps, no guessed timestamps, no synthesized fold counts. If the prose doesn't say it, ask. If the user doesn't remember, leave the field undefined (progressive render handles it).

**One commit per bake** — 12 bakes → 12 commits. Atomic, reviewable, reversible. Commit message format: `chore(bake-log): backfill structured stats for {recipe-id} {date}`.

## Out of scope

- Other recipe backfills (held until this exemplar lands)
- Schema changes (locked in PF-177.3 / PF-177.4)
