# Cost Data Readiness Audit (PF-211.4)

**Spike completed:** 2026-04-22
**Context:** Printable bake sheet needs per-recipe and per-serving cost. This audit maps where cost data lives, its completeness, and feasibility of per-serving derivation.

---

## Executive Summary

**Cost data is per-bake, not per-recipe.** The system stores historical ingredient cost snapshots on each `cook_log` entry. Cost calculation happens on the bake review page (`/review/bake/{recipe}/{date}`) where users select products from HEB search results, then wire the finalized `cost` object into the recipe JSON.

**Coverage:**
- **25/33 total cook_log entries** have cost data (76% coverage)
- **7 recipes** have at least one bake with cost
- **26 bakes** have HEB search results cached in `public/review-data/{recipe}/{date}/heb-results.json`
- **1 missing cost entry** despite HEB data: `simple-sourdough 2026-02-19`

**Per-serving feasibility:** ✅ **READY**. All recipes with cost data also have servings data (either `nutrition.servings` or `config.stats`).

**Key blocker for printout:** Cost is per-bake (historical), not per-recipe (canonical). Printout must either:
1. Use cost from the most recent bake (snapshot approach)
2. Derive a canonical recipe cost from HEB lookups + pantry rates on-demand

## Cost Data Schema

### CookLogCost (stored on cook_log entries)

```typescript
interface CookLogCost {
  total: number              // Total bake cost in USD
  perServing: number         // Cost per serving (total / servings)
  servings: number           // Number of servings for this bake
  items: CookLogCostItem[]   // Per-ingredient breakdown
  note?: string              // Optional cost note
}

interface CookLogCostItem {
  ingredientId: string       // Links to recipe ingredient
  name: string               // Ingredient display name
  sourceType: 'heb' | 'rate' | 'pantry' | 'manual'
  sourceName: string         // Product name or rate description
  amount: number             // Recipe amount used
  unit: string               // Unit (g, whole, etc.)
  cost: number               // Item cost in USD
}
```

### HebResultsFile (cached in review-data/)

```typescript
interface HebResultsFile {
  recipeId: string
  date: string               // Bake date (YYYY-MM-DD)
  storeId: number            // HEB store ID (default: 428)
  ingredients: HebIngredientResult[]
}

interface HebIngredientResult {
  ingredientId: string
  name: string
  recipeAmount: number
  recipeUnit: string
  products: HebProduct[]     // Up to 20 search results
}

interface HebProduct {
  name: string
  brand: string
  size: string               // "5 lbs", "17.6 oz", etc.
  sizeGrams: number          // Converted to grams
  price: number              // Regular price
  salePrice: number | null   // Sale price if on sale
  unitPrice: string          // "$0.07/oz"
  inStock: boolean
}
```

### CostRatesFile (pantry staples at public/cost-rates.json)

```typescript
interface CostRatesFile {
  updatedAt: string          // Last updated date
  source: string             // "H-E-B Store #428 (Austin, TX)"
  rates: Record<string, CostRate>
}

interface CostRate {
  name: string               // "Bread Flour"
  ratePerGram: number        // $/g rate
  sourceProduct: string      // "King Arthur Bread Flour, 5 lb @ $5.58"
  updatedAt: string
}
```

**Current rates:** `all_purpose_flour`, `bread_flour`, `starter`, `water`, `salt`, `granulated_sugar`, `yeast` (7 total)

## Per-Serving Derivation Feasibility

### Servings Data Sources

1. **nutrition.servings** (preferred) — explicit servings count from nutrition analysis
   - Present on: 18/23 recipes
   - Example: `simple-sourdough` → 10 servings

2. **config.stats** (fallback) — calculated as `defaultYield × servingsPerItem`
   - Present on: 20/23 recipes
   - Example: `sourdough-pizza-dough` → 2 pizzas × 8 slices = 16 servings

3. **Both** (overlap) — some recipes have both fields
   - `simple-sourdough`: nutrition.servings=10, stats=(2 loaves × 10 slices)=20
   - **Discrepancy:** Nutrition uses 1 loaf (10 servings), stats uses 2 loaves (20 servings)

### Per-Serving Calculation Logic

**Current implementation** (BakeReviewPage.vue):

```typescript
function parseServings(yields: string): number {
  const match = yields.match(/(\d+)/)
  return match ? parseInt(match[1], 10) : 1
}
```

Uses regex on `meta.yields` string. This is fragile (doesn't handle "8-10 slices").

**Recommended approach for printout:**

```typescript
function getServings(recipe: Recipe): number {
  // Priority 1: nutrition.servings (explicit, validated)
  if (recipe.nutrition?.servings) {
    return recipe.nutrition.servings
  }

  // Priority 2: config.stats (calculated)
  if (recipe.config.stats) {
    return recipe.config.stats.defaultYield * recipe.config.stats.servingsPerItem
  }

  // Priority 3: fallback to 1 (treat as single serving)
  return 1
}
```

## Blockers for Printout Feature

### 1. Cost is Per-Bake, Not Per-Recipe

**Problem:** The printable bake sheet is a canonical recipe reference, but cost is a per-bake historical snapshot.

**Scenarios:**

- **Simple Sourdough** has 17 bakes with cost data spanning 2026-02-16 to 2026-04-17
  - Cost per loaf ranges $1.26–$2.68 (depends on product selection + servings)
  - Which cost should the printout show?

**Solution options:**

A. **Most recent bake** — use `cook_log[].cost` from latest entry with cost data
   - Pros: Simple, reflects current pricing
   - Cons: Stale if user hasn't baked recently

B. **Live HEB lookup** — re-run HEB search + pantry rates on print
   - Pros: Always current
   - Cons: Slower, requires MCP server, might not match user's actual purchases

C. **User selects bake** — printout accepts `?bakeDate=YYYY-MM-DD` query param
   - Pros: Explicit choice
   - Cons: Requires UI picker

**Recommendation:** Start with A (most recent bake), add C if users request it.

### 2. Missing Cost Data on Some Bakes

**Current gaps:**

- `atk-cinnamon-buns-ultimate`: 0/2 bakes (0%)
- `ny-style-pizza`: 1/4 bakes (25%)
- `sourdough-pizza-dough`: 1/2 bakes (50%)

**Why?** Early bakes predate the cost feature (added Feb 2026). Review sessions may have been interrupted before cost picking.

**Impact on printout:** Recipes with 0% coverage will show "Cost data not available" instead of per-serving cost.

**Backfill feasibility:**

- HEB results files exist for 26 bakes
- 1 bake (`simple-sourdough 2026-02-19`) has HEB results but no cost in cook_log
  - Can be backfilled by opening `/review/bake/simple-sourdough/2026-02-19` and completing cost picker

**Recommendation:** Backfill the 1 missing cost entry. Leave early bakes (pre-cost-feature) as-is unless user requests backfill.

### 3. Servings Mismatch Between nutrition and stats

**Examples:**

- `simple-sourdough`:
  - `nutrition.servings: 10` (1 loaf, 10 slices)
  - `stats: 2 loaves × 10 slices = 20 servings`
- `ny-style-pizza`:
  - `nutrition.servings: 2` (unclear what this means — 2 pizzas or 2 slices?)
  - `stats: 2 pizzas × 8 slices = 16 servings`

**Root cause:** `nutrition` block was added later and reflects 1× yield, while `stats` reflects recipe default (often 2× for batch recipes).

**Impact on per-serving cost:**

- If printout uses `nutrition.servings`, cost is per-loaf/pizza (higher)
- If printout uses `stats`, cost is per-slice (lower, more granular)

**Recommendation:** Prefer `nutrition.servings` when present (nutritionist-verified). Fallback to `stats` only when `nutrition` is absent. Document the mismatch as a known issue.

### 4. No Cost Data Cleanup or Archival

**Observation:** `public/review-data/` contains 26 HEB results files totaling ~2MB (raw JSON).

**Future concern:** As cook_log grows (100+ bakes), review-data will bloat. No cleanup mechanism exists.

**Recommendation:** Out of scope for printout, but note as tech debt. Consider archiving review-data after cost is wired into cook_log (files become redundant once cost is committed).

## Data Quality Observations

### Cost Source Distribution

From sampled cost entries:

- **HEB products:** ~60% (fresh ingredients, specialty items)
- **Pantry rates:** ~30% (flour, water, salt, starter, sugar)
- **Manual/Other:** ~10% (user-entered prices)

### Cost Accuracy

**Strengths:**
- Product names preserved (`"King Arthur Unbleached Bread Flour"`)
- Source badges visible in UI (`HEB`, `RATE`, `PANTRY`)
- Per-ingredient cost tracked (granular)

**Weaknesses:**
- No date stamp on cost entries (tied to bake date, but prices may have changed)
- No sale price tracking in final cost (salePrice exists in HEB results but not preserved)
- Pantry rates (`cost-rates.json`) updated manually (last update: 2026-02-16)

**Impact on printout:** Cost shown on printout may be slightly stale (1-2 months old for pantry rates).

## Recommendations

### For Printout Implementation (PF-211)

1. **Use most recent bake cost** as default recipe cost
   - Query: `cook_log.filter(e => e.cost).sort((a, b) => b.date - a.date)[0]`
   - Fallback: "Cost data not yet available" if no cost entries

2. **Derive servings** from `nutrition.servings` first, fallback to `stats`
   - Use `getServings()` helper function (see above)
   - Document mismatch between nutrition (1×) and stats (default batch)

3. **Show cost breakdown** on printout (optional enhancement)
   - Total cost
   - Per-serving cost
   - Date of cost snapshot (bake date)
   - Note: "Based on {date} bake. Prices may vary."

4. **Handle missing cost gracefully**
   - Recipes without cost: hide cost section or show placeholder
   - Don't block printout if cost is missing

### For Future Cost Infrastructure

1. **Add cost date tracking** — timestamp when cost was calculated (distinct from bake date)
2. **Expose cost picker for recipes without bakes** — allow canonical recipe costing independent of cook_log
3. **Automate pantry rate updates** — script to refresh `cost-rates.json` quarterly via HEB MCP
4. **Archive review-data** — move HEB results to archive/ after 90 days or after cost is committed

## Conclusion

**Per-serving cost derivation is READY for printout.** All recipes with cost data also have servings data (100% coverage). The main decision is **which bake's cost to use** (recommend: most recent). Missing cost data on some recipes is acceptable — printout should gracefully handle absence.

**Next steps for executor:**
1. Implement most-recent-bake cost lookup
2. Add servings derivation helper (`getServings()`)
3. Design cost section on printout (total, per-serving, date note)
4. Test with recipes that have cost (simple-sourdough, gochujang-garlic-buns) and without (atk-cinnamon-buns-ultimate)
