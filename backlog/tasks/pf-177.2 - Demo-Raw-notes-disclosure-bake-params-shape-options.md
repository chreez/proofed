**Option B — Grouped by phase**
```ts
interface BakeStatsBlock {
```

## Demo spike complete — schema locked

**Decision: Option A — flat scalars + arrays on `bake_stats`**

Picked over Option B (grouped: `bulk.start_time` / `bake.preheat`) and Option C (event-stream timeline) on three criteria the user specified:

1. **Easiest to maintain** — flat top-level fields, no nested object navigation, no event-type discriminators
2. **Easiest to backfill** — each field is independently optional; you can fill `dough_temps` for one bake and skip everything else without violating any structural assumption
3. **Most flexible across recipe types** — non-sourdough recipes don't fit a `mix → bulk → shape → bake` skeleton. Flat fields let any recipe declare its own subset via `bakeStatsSchema` without fighting a forced hierarchy

**Locked schema** (lives in PF-177.3 ACs):

```ts
interface BakeStatsBlock {
  dough_temps?: Array<{ time: string; temp_f: number }>
  bulk_ambient_temps?: Array<{ date: string; temp_f: number; note?: string }>
  bake_phases?: Array<{
    stage: 'preheat' | 'covered' | 'uncovered'
    start_time?: string
    temp_f: number
    duration_min: number
  }>
  stretch_folds?: Array<{
    time: string
    type: 'stretch_fold' | 'coil' | 'lamination'
    note?: string
  }>
  aliquot_rises?: Array<{
    time: string
    rise_pct: number
    stage: 'bulk' | 'preshape' | 'final'
    note?: string
  }>
}
```

**Visual contract** (also locked from demo iterations):

- **Tiles row**: dough avg (`73°F / AVG DOUGH / OVER 15H`), starter rise, bulk hours, total mass, etc.
- **Bake phases block**: explicit table — `preheat / 13:15 / 500°F / 45m // covered / 14:00 / 500°F / 20m // uncovered / 14:20 / 475°F / 25m`. User confirmed this render is correct; do NOT collapse to a count tile
- **S&F block**: type / time / note table
- **Aliquot rises block**: time / rise% / stage / note table with safe `parseInt` for `~100%` strings

**Raw notes disclosure** (also locked): verbatim notepad string in `raw_notes?: string` on `CookLogEntry`, rendered as collapsed `<details>` block below structured stats.
