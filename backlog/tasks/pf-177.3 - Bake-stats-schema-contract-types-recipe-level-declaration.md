## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define the TypeScript schema contract for per-recipe bake stats. Each recipe declares which structured stats fields it tracks via `config.bakeStatsSchema`. Per-bake data lives in `cook_log[].bake_stats` and `cook_log[].raw_notes` (PF-177.4 wires those in).

## Locked schema (Option A — flat scalars + arrays)

```ts
export interface BakeStatsBlock {
  dough_temps?: Array<{ time: string; temp_f: number }>
  bulk_ambient_temps?: Array<{ date: string; temp_f: number; note?: string }>
  bake_phases?: Array<{
    stage: 'preheat' | 'covered' | 'uncovered'
    start_time?: string
    temp_f: number
    duration_min: number
  }>
  stretch_folds?: Array<{
    time: string
    type: 'stretch_fold' | 'coil' | 'lamination'
    note?: string
  }>
  aliquot_rises?: Array<{
    time: string
    rise_pct: number
    stage: 'bulk' | 'preshape' | 'final'
    note?: string
  }>
}

export interface BakeStatsSchema {
  fields: Array<keyof BakeStatsBlock>
}

// RecipeConfig gets: bakeStatsSchema?: BakeStatsSchema
```

All fields optional. No forced migration. Time format: `YYYY-MM-DD - HH:MM` 24-hour. Schema picked from PF-177.2 demo iteration based on three criteria: easiest to maintain, easiest to backfill, flexible across recipe types (cookies/pizza/etc. just omit irrelevant arrays).

This is the type-only landing — no UI or capture work yet (PF-177.4 / PF-177.5 / PF-177.6).
