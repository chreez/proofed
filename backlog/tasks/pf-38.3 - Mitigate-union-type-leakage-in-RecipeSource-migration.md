## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Risk from PF-38.1 spike: changing `meta.source` from `string` to `string | RecipeSource` forces type guards in every consumer. Investigate whether to use a normalizer composable (e.g., `useRecipeSource()` that always returns a resolved object) vs. migrating all JSON to structured format and dropping string support entirely. Goal: zero type guards in components.
<!-- SECTION:DESCRIPTION:END -->

## Changes

Added a `normalizeSource()` function to the data layer so components always receive a structured `RecipeSource` object, never a raw string.

### Type system (`src/types/recipe.ts`)
- Added `RecipeSource` interface: `{ name: string; url?: string; type?: 'original' | 'adapted' | 'inspired'; author?: string; accessed?: string }`
- Changed `RecipeMeta.source` from `string` to `RecipeSource`

### Data layer (`src/composables/useRecipe.ts`)
- Added exported `normalizeSource(source: unknown): RecipeSource | undefined`
  - `string` → `{ name: source }`
  - Already-structured object with `name` → pass through
  - `null` / `undefined` / invalid → `undefined`
- Applied normalizer at `loadRecipe()` after JSON parse, before setting `currentRecipe.value`

### Component (`src/components/RecipeMeta.vue`)
- Template line 87: `{{ recipe.meta.source }}` → `{{ recipe.meta.source.name }}`
- No type guard needed — normalizer guarantees the shape

### Tests
- `useRecipe.spec.ts`: 5 new tests for `normalizeSource()` (string, object, null, undefined, invalid object)
- `RecipeMeta.spec.ts`: fixture updated to structured source object
- `App.spec.ts`: fixture updated to structured source object
- All 355 tests pass

### Build
- `npm run build` passes (tests + vue-tsc + vite build)
- Pre-commit hook passed
