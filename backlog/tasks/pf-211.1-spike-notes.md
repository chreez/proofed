# PF-211.1 Spike Notes: Print CSS & QR Code Tech Audit

**Task:** Research print route architecture, QR code libraries, and CSS print best practices for proofed. printable bake sheets.

**Target:** Letter-size (8.5×11) single-page layout with overflow to 2 pages for complex recipes. No photos. Dedicated `/recipe/:id/print` route.

---

## Executive Summary

**Recommended Stack:**
- **QR Library:** `qrcode` (already installed) — 38.1 kB minified, 10.5 kB gzipped
- **Print CSS:** UnoCSS `print:` variants + `@page` at-rule in dedicated print stylesheet
- **Architecture:** Dedicated print route with lazy-loaded print component

**Key Decision:** Use the existing `qrcode` library (already in package.json) instead of `qr-code-styling` (also installed). The simpler library is sufficient for print use cases and has 4x smaller bundle size.

## 1. QR Code Library Comparison

### Already Installed Libraries

The project currently has **three** QR code libraries installed:

```json
"qr-code-styling": "^1.9.2",
"qrcode": "^1.5.4",
"uqr": "^0.1.2"
```

### Library Analysis

| Library | Bundle Size | Gzipped | Weekly Downloads | Last Updated | Vue 3 Support | Use Case |
|---------|-------------|---------|------------------|--------------|---------------|----------|
| **qrcode** | 38.1 kB | 10.5 kB | 4.3M | 2 years ago | ✅ (vanilla JS) | Simple QR generation, multiple output formats |
| **qr-code-styling** | 139 kB | ~40 kB | 207K | Active | ✅ (vanilla JS) | Styled QR codes with logos, gradients, rounded corners |
| **uqr** | ~10 kB | ~3 kB | 73 dependents | Recent | ✅ (universal) | Minimal, multi-format (ANSI, Unicode, SVG) |
| **@paulmillr/qr** | 232.3 kB unpacked | N/A | N/A | Active (2026) | ✅ | Zero-dep, encoder + decoder, multiple formats |

### Recommendation: Use `qrcode`

**Rationale:**
- Already installed (no new dependency)
- 4x smaller than `qr-code-styling` (10.5 kB vs 40 kB gzipped)
- Mature, stable library (4.3M weekly downloads)
- Supports canvas and data URL output — perfect for print
- No styling needed for print use case (basic black/white QR is ideal for scanning)

**Why not the others:**
- `qr-code-styling`: Overkill for print. Styling features (logos, gradients) not needed and add 30 kB.
- `uqr`: Smaller but less battle-tested. `qrcode` is the industry standard.
- `@paulmillr/qr`: Not currently installed. `qrcode` is sufficient.

**Current Usage:** The project uses `qr-code-styling` in `DemoQrPrintTest.vue` for testing print label maker scanning. For the actual print route, switch to `qrcode` for simpler, smaller output.

### Implementation Pattern

```typescript

  errorCorrectionLevel: 'M',
  margin: 4,
  width: 200,
  color: {
    dark: '#1a1816', // proofed ink
    light: '#ffffff'
  }
})
```

## 2. Dedicated Print Route Architecture

### Router Setup

Add to `src/router/index.ts`:

```typescript
{
  path: '/recipe/:recipeId/print',
  name: 'recipe-print',
  component: EmptyRouteView,
  meta: { showIndex: false, printMode: true }
}
```

**Why EmptyRouteView pattern?**
- Matches existing project convention (see all current routes)
- App.vue handles route-based rendering via computed flags
- Keeps print component lazy-loaded until needed

### App.vue Integration

```typescript
// Derive page state from route
const showPrintMode = computed(() => route.name === 'recipe-print')
```

```vue
<template>
  <!-- ... existing routes ... -->
  <PrintView v-if="showPrintMode" :recipe-id="currentRecipeId" />
</template>
```

### Component Structure

**File:** `src/components/PrintView.vue`

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { useRecipe } from '@/composables/useRecipe'
import QRCode from 'qrcode'
import type { Recipe } from '@/types/recipe'

const props = defineProps<{
  recipeId: string
}>()

const { currentRecipe } = useRecipe()

// Generate QR code URL
const qrCodeUrl = computed(async () => {
  if (!props.recipeId) return ''
  const url = `https://proofeddot.netlify.app/recipe/${props.recipeId}`
  return await QRCode.toDataURL(url, {
    errorCorrectionLevel: 'M',
    margin: 4,
    width: 200,
    color: { dark: '#1a1816', light: '#ffffff' }
  })
})
</script>

<template>
  <div class="print-container">
    <!-- Print-specific layout -->
  </div>
</template>

<style>
/* Print-specific styles - see section 3 */
</style>
```

**References:**
- Existing router pattern: `src/router/index.ts`
- Demo component examples: `src/components/DemoQrPrintTest.vue`, `src/components/DemoSharedMode.vue`

## 3. Print CSS Approach

### UnoCSS Print Utilities

UnoCSS supports print media variants via the `print:` prefix (also available as `_print:`).

**Example:**
```html
<div class="mt-4 print:mt-0 bg-stone-100 print:bg-white">
  <!-- Margin-top 1rem on screen, 0 in print -->
  <!-- Background stone-100 on screen, white in print -->
</div>
```

**Limitations:**
- UnoCSS variants work for utility-level overrides
- Complex print rules (page size, margins, break control) need dedicated `@page` CSS

**Recommendation:** Use **both** UnoCSS `print:` utilities + dedicated print stylesheet.

### @page CSS Rules

**File:** `src/components/PrintView.vue` (scoped style block)

```css
@media print {
  @page {
    size: letter portrait;
    margin: 0.75in 0.5in; /* top/bottom, left/right */
  }

  /* Prevent page breaks inside critical blocks */
  .stage-block,
  .ingredient-list,
  .state-list {
    break-inside: avoid;
    page-break-inside: avoid; /* fallback for older browsers */
  }

  /* Control orphans and widows */
  p, li {
    orphans: 3;
    widows: 3;
  }

  /* Force page breaks before major sections if needed */
  .force-page-break {
    break-before: page;
    page-break-before: always; /* fallback */
  }

  /* Hide interactive elements */
  button,
  .fab,
  .toc-sidebar,
  .header-actions {
    display: none !important;
  }
}
```

**Key CSS Properties:**
- **`size: letter portrait`** — Enforces 8.5×11 inch page size
- **`margin`** — Defines printable area (0.75in top/bottom = ~54pt, safe margin for most printers)
- **`break-inside: avoid`** — Prevents splitting of ingredient lists, state blocks, etc.
- **`orphans: 3` / `widows: 3`** — Prevents lone lines at page breaks
- **`break-before: page`** — Forces section to start on new page (use sparingly)

### Single-Page Target with Overflow Strategy

**Goal:** Fit most recipes on 1 page, allow 2 pages for complex recipes (e.g., Tartine Baguette with 20+ states).

**Approach:**
1. **Aggressive condensing** — reduce whitespace, tighter line-height, smaller fonts in print
2. **Smart truncation** — omit verbose notes, keep only critical step info
3. **Two-column layout** — ingredients left, instructions right (space-efficient)
4. **Conditional sections** — hide version history, nutrition, cook log in print mode

**Implementation:**

```vue
<div class="grid grid-cols-2 gap-4 print:gap-2">
  <div class="col-span-1">
    <!-- Ingredients column -->
  </div>
  <div class="col-span-1">
    <!-- Instructions column -->
  </div>
</div>
```

```css
@media print {
  body {
    font-size: 10pt;
    line-height: 1.3;
  }

  h1 { font-size: 16pt; margin-bottom: 8pt; }
  h2 { font-size: 12pt; margin-bottom: 6pt; }
  h3 { font-size: 10pt; margin-bottom: 4pt; }

  /* Condense spacing */
  .stage-card { margin-bottom: 12pt; padding: 8pt; }
  .state-list { margin-bottom: 6pt; }

  /* Hide non-essential sections */
  .version-timeline,
  .cook-log-section,
  .nutrition-section {
    display: none;
  }
}
```

**Overflow handling:**
- If content exceeds 1 page, browser automatically flows to page 2
- `break-inside: avoid` ensures logical sections stay together
- Recipe title + meta info repeated in footer via `@page` margin boxes (future enhancement)

## 5. Design Tokens in Print Mode

**Proofed brand identity must carry through to print:**

```css
@media print {
  /* Proofed color palette for print (grayscale-friendly) */
  --color-ink: #1a1816; /* text */
  --color-stone-200: #e8e4dc; /* light backgrounds → white in print */
  --color-accent: #a65d45; /* accent → used sparingly, may render as gray on B&W printers */

  /* Typography */
  font-family: 'Inter', system-ui, sans-serif; /* body text */

  .brand-name {
    font-family: 'JetBrains Mono', monospace; /* proofed. logo */
  }

  /* Borders: 2px solid, 0 border-radius */
  .print-card {
    border: 2px solid #1a1816;
    border-radius: 0;
  }
}
```

**Grayscale considerations:**
- Assume user may print on B&W printer
- Accent color (#a65d45) may render as mid-gray
- Use ink (#1a1816) for all critical text and borders
- Avoid relying on color alone for meaning (use icons, weight, borders)
