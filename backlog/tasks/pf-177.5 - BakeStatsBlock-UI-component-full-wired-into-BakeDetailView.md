## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Build the full `BakeStatsBlock.vue` component (3-pill header + 6 sections + raw notes disclosure) and wire it into `BakeDetailView.vue`. Because placement affects reading flow, build a small side-by-side placement demo so HITL can pick between "between Summary and Hero" vs "after Notes." After placement is chosen, backfill structured `bake_stats` onto all 13 simple-sourdough cook log entries using best-effort extraction from existing prose notes — **raw `notes[]` arrays must stay intact on every entry** (structured data supplements, never replaces).

## Scope (3 bundled concerns)

**A. Component + wiring**
- `src/components/BakeStatsBlock.vue` — full form (7 sections below)
- Wire into `BakeDetailView.vue` at chosen placement (TBD via demo review)

**B. Placement demo**
- `src/components/DemoBakeDetailPlacements.vue` (throwaway)
- Route `/demo/bake-detail-placements`
- Two BakeDetailView mocks side-by-side (or stacked on mobile):
  - **Option A:** BakeStatsBlock between Summary and Hero photo
  - **Option B:** BakeStatsBlock after Notes block, before Cost Breakdown
- Both mocks use the same bake entry

**C. Backfill**
- All 13 simple-sourdough `cook_log` entries get a `bake_stats` block
- Values extracted best-effort from existing prose `notes[]`
- `confidence` assigned per entry:
  - `high` → timestamps + explicit temps/rises in notes
  - `medium` → partial structure, some inference
  - `low` → fully recalled, falls back to `bake_defaults.bake_phases`
- **`notes[]` arrays byte-identical** — zero prose changes
- Recipe minor version bump with changelog entry

## Full BakeStatsBlock layout (7 sections, progressive render)

1. **3-pill header** (reuse Variant B from PF-177.9): `bulk {hrs}` / `proof {hrs}` / `bake {hrs}`
2. **Low-confidence callout** (only when `confidence === 'low'`): inline note explaining data was reconstructed from memory
3. **Temperatures section** — dough temps timeline + bulk ambient averages (tiles + raw array)
4. **Stretch & folds** — 4-col grid with day-break dotted rule
5. **Aliquot rises** — 4-col grid with rise bars + day-break dotted rule
6. **Bake phases** — 4-col grid (STAGE / START TIME / TEMP / DURATION), uppercase stage labels; falls back to `recipe.bake_defaults.bake_phases`
7. **Raw notes disclosure** — `[▸ Show raw notes]` toggle that reveals the prose `notes[]` array verbatim

## Reference

- PF-177.1 and PF-177.2 demos are the visual reference for the section patterns (4-col grids, day-break rules, rise bars)
- PF-177.9 (`CookLogSection.vue`) ships the compact 3-pill variant that the header reuses
- `recipe.bake_defaults.bake_phases` already exists at the root of `simple-sourdough.json` (PF-177.9 v4)
- Helper extraction (e.g., `useBakeStats.ts` composable) left to subagent's judgment based on component size
