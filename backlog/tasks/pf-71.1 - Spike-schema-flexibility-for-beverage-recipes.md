## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The proofed. recipe schema is built around baking stages (PREP/RISE/BAKE/COOL) with timer:true only on passive states. Thai Tea Boba is a beverage — no oven, no rise, no bake. Investigate how the stage/state model maps to non-baking recipes.\n\nQuestions to answer:\n- Do existing stage types (prep/cook/assembly) cover beverage workflows, or do we need new types?\n- Timer states: steeping tea and cooking boba are timed but not passive in the baking sense — how should timer:true apply?\n- Parallel prep: tea brews while boba cooks — can stages run concurrently?\n- The 2-hour boba window is a critical constraint — how to model time-sensitive serving windows?\n- Are there other recipe categories (salads, sauces, drinks) that would stress the schema similarly?
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Spike Findings\n\n### Schema is already generic — no TypeScript changes needed\n- Stage IDs are freeform strings, not an enum\n- `timer: true` already used on 10+ non-RISE/BAKE/COOL states (AUTOLYSE_REST, FERMENT_POOLISH, COOK_RICE, etc.)\n- `parallel: true` on states + notes handles concurrent hints (curry, tartine precedent)\n- 2-hour boba window → critical note on DRAIN_TOSS_SYRUP state\n- Hot variant → separate recipe JSON in family (cinnamon bun variant pattern)\n\n### Checklist wording updates needed\n- **D4**: Reword to \"timer: true only on passive/waiting states\" (drop RISE/BAKE/COOL enumeration)\n- **D7**: Reword to \"gather sections on stages that introduce new ingredients\" (overnight buns already break current rule)\n\n### Proposed stage mapping (iced)\nPREP → BREW_TEA (simmer 3m, steep 15-20m, chill 30m) → MAKE_BOBA_SYRUP → COOK_BOBA (5-7m) → MIX_MILK → ASSEMBLE\n\n### Other categories tested\nSalads, sauces, cocktails, sous vide all fit the existing schema comfortably."
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Schema is already generic enough for beverage recipes — no TypeScript interface changes needed. Stage IDs are freeform strings, timer:true is already used beyond RISE/BAKE/COOL. Only validation checklist wording needs updating: D4 (timer rule) and D7 (gather rule). Proposed 6-stage mapping for Thai Tea Boba. Hot variant fits existing family/variant pattern.
