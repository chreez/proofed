## 1. FDA Big 9 Allergen List (Canonical Reference)

The **FDA Big 9** major food allergens, per the FALCPA law as amended by the FASTER Act (effective January 1, 2023):

1. **Milk**
2. **Eggs**
3. **Fish** (e.g., bass, flounder, cod)
4. **Crustacean Shellfish** (e.g., crab, lobster, shrimp)
5. **Tree Nuts** (e.g., almonds, walnuts, pecans)
6. **Peanuts**
7. **Wheat**
8. **Soybeans**
9. **Sesame** (added 2021, effective 2023)

**Official Sources:**
- [USDA FSIS: Food Allergies - The "Big 9"](https://www.fsis.usda.gov/food-safety/safe-food-handling-and-preparation/food-safety-basics/food-allergies-big-9)
- [FDA: Food Allergies](https://www.fda.gov/food/nutrition-food-labeling-and-critical-foods/food-allergies)
- [FDA: Food Allergies - What You Need to Know](https://www.fda.gov/food/buy-store-serve-safe-food/food-allergies-what-you-need-know)

## 2. Approach Evaluation

### Option A: Hardcoded Lookup Table
A static mapping of ingredient ID → allergen tags.

**Pros:**
- Simple to implement
- No manual per-recipe work
- Deterministic and maintainable

**Cons:**
- Requires initial ingredient audit (one-time cost)
- Edge cases need manual review

### Option B: Manual Per-Recipe Tagging
Add `"allergens": ["wheat", "milk", "eggs"]` to each recipe JSON.

**Pros:**
- Recipe author has full control
- Can handle brand-specific differences

**Cons:**
- Error-prone (manual entry)
- Duplicate work across recipes
- No single source of truth

### Option C: Hybrid (Recommended)
Hardcoded lookup table as default + optional per-recipe override.

**Pros:**
- DRY principle — ingredient mapping is centralized
- Flexibility for edge cases
- Easy to audit and update

**Cons:**
- Slightly more complex implementation

|------------|-------|------------|
| `ghee` | Milk-derived but lactose-free | **Tag as Milk** — still dairy protein present |

| `curry_roux` | Multi-allergen commercial product | **Tag as Wheat, Peanuts, Milk, Soybeans** (House Foods Java Curry label) |
| `beef_broth` | May contain celery | Celery not Big 9 — no tag needed |
| `beer` | Gluten from barley/wheat | **Tag as Wheat** (gluten-containing grain) |

## 5. Recommended Approach

**Hybrid Model: Hardcoded Lookup Table + Per-Recipe Override**

### Rationale
- **Proportional to ~10 recipes:** Hardcoded table is low-effort, high-reward
- **Avoids over-engineering:** No complex tagging UI needed
- **Future-proof:** New recipes automatically inherit allergen data
- **Flexible:** Per-recipe overrides available if needed (e.g., gluten-free variant)

### Implementation Steps
1. Create `src/data/allergenMap.ts` with ingredient ID → allergen array mapping
2. Add optional `allergenOverride?: string[]` field to recipe JSON schema
3. Compute allergens at build/runtime by merging ingredient IDs from `gather.ingredients[]` with `allergenMap`
4. Display on recipe page as **"Contains: Wheat, Milk, Eggs, Tree Nuts (almonds)"** with Big 9 emphasis
5. **No cross-contamination tracking** — presence-only declaration

## 6. Proposed JSON Schema

### Option A: Centralized Lookup (Recommended)
**File:** `src/data/allergenMap.ts`

```typescript
export const allergenMap: Record<string, string[]> = {
  // Dairy
  butter: ['Milk'],
  milk: ['Milk'],
  cream_cheese: ['Milk'],
  ghee: ['Milk'],
  cheese: ['Milk'],

  // Eggs
  eggs: ['Eggs'],

  // Wheat
  flour: ['Wheat'],
  ap_flour: ['Wheat'],
  bread_flour: ['Wheat'],
  starter: ['Wheat'], // assumes wheat-based

  // Tree Nuts
  almond_flour: ['Tree Nuts (almonds)'],

  // Peanuts
  peanut_butter: ['Peanuts'],

  // Soy
  soy_sauce: ['Soybeans', 'Wheat'],
  light_soy_sauce: ['Soybeans', 'Wheat'],
  miso: ['Soybeans'],
  gochujang: ['Soybeans', 'Wheat'],
  worcestershire: ['Fish (anchovies)', 'Soybeans'],
  chuno_sauce: ['Soybeans'],

  // Sesame
  sesame_seeds: ['Sesame'],

  // Multi-allergen products
  curry_roux: ['Wheat', 'Peanuts', 'Milk', 'Soybeans'],

  // Grains (gluten-containing)
  beer: ['Wheat'],

  // Chocolate (context-dependent)
  chocolate: [], // Override per recipe if milk chocolate vs. dark
};
```

**Recipe JSON (no changes needed unless override):**
```json
{
  "meta": {
    "allergenOverride": ["Wheat", "Milk", "Eggs"]
  }
}
```

**Computed Display Logic:**
```typescript
function getRecipeAllergens(recipe: Recipe): string[] {
  if (recipe.meta.allergenOverride) {
    return recipe.meta.allergenOverride;
  }

  const allergens = new Set<string>();
  recipe.stages.forEach(stage => {
    stage.gather?.ingredients?.forEach(ing => {
      const tags = allergenMap[ing.id] || [];
      tags.forEach(tag => allergens.add(tag));
    });
  });

  return Array.from(allergens).sort();
}
```

### Option B: Per-Recipe Manual Tags (Not Recommended)
```json
{
  "meta": {
    "allergens": ["Wheat", "Milk", "Eggs", "Tree Nuts (almonds)"]
  }
}
```

**Why Not:** Violates DRY, error-prone, no single source of truth.

## 8. Recommendation Summary

✅ **Use Hybrid Model: Hardcoded Lookup Table + Optional Override**

**Justification:**
- Simple to implement (~50 lines of TypeScript + data file)
- Scales to ~10 recipes without manual work
- Single source of truth for ingredient → allergen mapping
- Audit trail: all mappings visible in `allergenMap.ts`
- Flexible for edge cases (e.g., gluten-free flour swap)
