Three patterns for the production-queue compose workflow. PF-256.1 shipped a button+modal+list UX that felt "awkward" — desktop needs drag-and-drop-style browsing, not modal pop-ups.

Each demo runs with the same 12 recipes pulled from public/recipes/index.json. Each includes a populated and an empty state, plus tradeoff notes at the bottom.

Spec: PF-256.2 · Parent: PF-256 · Mobile = separate workflow (review-only)
Mobile note All three demos degrade on mobile (≤640px) to a review-mode list — single-column queue, no library composition. Mobile is the "review what's in the queue" workflow, not the "build the queue" workflow.

Selection rubric

Pick the layout that best supports the actual user flow: "I have a vague idea what I want to bake; let me browse + drag together a queue, adjust quantities, and head to the shopping list." Compose-heaviness, discovery, and context retention vary across the three. Test all three in the browser at the URLs above before committing.
