Experiment Panel: Layout Options

Three placement approaches for the ingredient adjustment panel. Each renders functional sliders with derived values that update in real time. Evaluate visual fit, scroll behavior, and mobile UX.

Mobile Behavior
On mobile, this section scrolls naturally with the page. User scrolls past it if not needed. Same collapse/expand interaction as stage cards — no new interaction pattern to learn.
Advantages
  • Consistent with existing section patterns
  • No overlay z-index complexity
  • Accessible — standard expand/collapse
  • Works identically on mobile and desktop
  • Can be placed contextually near relevant stage
Disadvantages
  • Scrolls out of view when browsing other stages
  • Can't see derived values while reading a distant step
  • Takes vertical space in the recipe flow
  • Position is fixed — always between same stages

Mobile Behavior
On mobile, the drawer would need to become a full-width overlay or bottom sheet, since 320px leaves too little room for recipe content. This means maintaining two interaction patterns.
Advantages
  • Always visible while scrolling recipe
  • Derived values stay in view at all times
  • Doesn't interrupt recipe stage flow
  • Can be opened/closed without losing scroll position
Disadvantages
  • Competes with TOC sidebar for right-side space
  • Narrows recipe content area when open
  • Requires different pattern on mobile (dual UX)
  • Z-index complexity with sticky header + TOC
  • Not a pattern used elsewhere in proofed.
Option C
Bottom Sheet / Overlay
Fixed to viewport bottom with a peek bar showing key values. Slides up to reveal full controls. Mobile-native pattern, but evaluate desktop ergonomics.

Mobile Behavior
This IS the mobile pattern. The peek bar shows key values without opening. Swipe or tap to expand. On desktop, the bottom-pinned sheet feels less natural — users expect side panels or inline content. The FAB trigger (gear icon, bottom-right) opens the sheet from its collapsed state.
Advantages
  • Excellent mobile UX — native bottom sheet feel
  • Peek bar shows key derived values at a glance
  • Doesn't take recipe page space when collapsed
  • Scrim focuses attention when expanded
Disadvantages
  • Feels foreign on desktop — bottom-anchored panels are mobile patterns
  • Blocks recipe content when expanded (modal-like)
  • Covers FAB and other bottom-positioned UI
  • Scrim creates cognitive interruption
  • Competes with existing FAB (general notes)
Summary
Evaluation Notes

Option A (Collapsible) is the most consistent with existing proofed. patterns. No new interaction model to learn. The tradeoff is losing visibility when scrolling away.

Option B (Drawer) keeps the panel always accessible but conflicts with the TOC sidebar position and requires a separate mobile pattern. Two interaction models to maintain.

Option C (Bottom Sheet) is the strongest mobile solution but awkward on desktop. The peek bar is a nice touch for passive monitoring, but the modal expansion breaks flow.

Hybrid approach worth considering: Option A for desktop (inline, contextual), with Option C's peek bar on mobile only. This would give each platform its native pattern without forcing a single compromise.
