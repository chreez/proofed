PF-187: Reset Bake Confirmation Dialog

Context: The reset bake button (RotateCcw icon) currently clears all progress with no warning. This demo shows 3 design options for a confirmation dialog. Data shown: 3 checked items, 2 completed stages, 1 scratchpad note.
Option A: Bottom Sheet
Mobile-first, slides up from bottom. Drag to dismiss. Matches existing BottomSheet.vue pattern.
Confirm Reset
You will lose:
3 checked items (vessels, equipment, ingredients)
2 completed stages
1 scratchpad note
Option B: Center Modal
Desktop-focused, centered with fixed width. Matches existing ShareModal.vue pattern. Escape key closes.
Reset Bake?
This will clear all your progress and notes for this bake. This action cannot be undone.
Will be lost:
3 checked items
2 completed stages
1 scratchpad note
Option C: Inline Confirmation
Replaces button area with inline confirmation. No modal, stays on page. Most minimal approach.
Hover over Reset button →
Reset all bake progress?
This will clear your checked items, completed stages, and scratchpad notes.
Data loss:
3 items • 2 stages • 1 note
Analysis & Recommendations
Option A (Bottom Sheet): Best for mobile, drag-to-dismiss is intuitive. Consistent with existing BottomSheet.vue. Takes up full viewport height on mobile but minimal on desktop (scrollable). Most accessible for thumb interaction.
Option B (Center Modal): Desktop-native feel, centered focus. Matches ShareModal.vue pattern already in codebase. Fixed width (360px max) is clean on both mobile and desktop. Supports Escape key for accessibility. Best consistency with existing modals.
Option C (Inline Confirmation): No modal layer, stays in context of the button. Lowest visual weight. However, requires replacing the button area entirely, which might confuse users about where the reset button went.
Recommendation: Option B (Center Modal) balances consistency, accessibility, and clarity. The codebase already has ShareModal.vue which provides a proven pattern. It works well on all screen sizes and follows web conventions (Escape to close, click-outside to dismiss).
Alternative pick: If mobile-first is priority, Option A (Bottom Sheet) is more natural for thumb interaction and takes advantage of existing BottomSheet.vue component.
Implementation notes: Regardless of choice, the dialog should display dynamic stats: calculate checked items from progress state, count completed stages, and fetch scratchpad.totalEntryCount. Show "nothing to reset" state if progress.hasProgress.value is false.
