Pattern Comparison
Criteria A: Sidebar/Sheet B: Floating Pill C: Inline Collapsible
Always visible (desktop) Yes Pill only No
Minimal viewport intrusion Sidebar takes space Very small Collapsed is small
Consistent across breakpoints Different UI patterns Same interaction Same interaction
Shows progress at a glance Full list visible Pill shows X/Y Only when expanded
Works while scrolling Sticky sidebar Fixed position Scrolls away
Implementation complexity High (2 patterns) Low (1 pattern) Low (1 pattern)
Touch-friendly Bottom sheet is Large tap target Full-width tap
Recommendation: Pattern B (Floating Pill)
Pattern B is the recommended approach for proofed. because:
  • Consistency: Same interaction model on mobile and desktop reduces cognitive load
  • Minimal footprint: A small pill preserves maximum space for recipe content, critical on mobile
  • Progress visibility: "Filling 2/4" instantly communicates where you are and how far along
  • Works while cooking: Fixed position means it is always accessible even mid-scroll
  • Simple implementation: One component, one behavior, fewer edge cases
  • Extensible: Easy to add Cook Log and Version History as separate section group in dropdown

Secondary choice: Pattern C (Inline Collapsible) is good if you want the TOC to feel more integrated with the content rather than floating. Consider using it in combination with Pattern B if you want both a persistent indicator and an inline overview.
